# 📋 需求优先级判断 SOP

> SOP 已推行 2 周，归档并追踪效果。

---

## 归档备注

- **推行日期**：2026-06-08
- **推行时长**：2 周
- **推行范围**：产品 + 技术团队（8 人）
- **可复用部分**：四维评分框架 + 决策记录模板

---

## 📦 复盘

**SOP 推行 2 周的效果：**
- 需求评审中优先级争吵次数：从月均 3 次 → 2 周内 0 次
- 团队反馈：「有标准比没标准好，至少不用猜老板怎么想」
- 一个小问题：「紧急」的定义还是太模糊，有人用「紧急」绕过评分

**下次可以改进的：**
- 给「紧急」加一个明确的定义：只有线上 P0/P1 故障才算紧急
- 评分过程应该更透明——把评分表发到群里，而不是会上口头打分
- 每月回顾一次评分记录，看看哪些维度的权重需要调整

**可复用的规则：**
```
当同一类冲突出现 3 次以上时，
优先建 SOP（标准化决策流程），
避免每次靠人治。
```

**可迁移的经验：**
- SOP 的核心不是「文档」，而是「双方都认可的标准」
- 权重可以调整，但必须有权重——模糊的标准等于没有标准
- 推行 SOP 时先从小范围试点，再扩展到全团队
