# 🏗️ Obsidian 系统结构图

> 方法论不该只活在脑子里。一个能用的系统只需要四件事：能存、能连、能查、能复用。

---

## 入门版：5 个文件夹

不需要五十个插件。先用这套结构跑起来：

```
📁 我的知识操作系统
├── 📁 00_万法 (开箱即用·Hub)      ← 中枢：模板、方法论、Prompt、规则
├── 📁 10_一心 (随手丢·Inbox)     ← 火种：灵感、日记、速记、问题
├── 📁 20_二旋 (磨一磨·Lab)       ← 施工：正在写的草稿、AI 对话、调试记录
├── 📁 30_三进阶 (出锅了·Output)  ← 成果：完成的文章、SOP、可交付物
└── 📁 40_四归藏 (存起来·Archive) ← 归档：不再活跃的旧内容
```

**为什么是这 5 个？**

因为它们对应的是知识的**生命周期**：

```
想法出现 → 10_一心 (随手丢·Inbox)
开始动手 → 20_二旋 (磨一磨·Lab)
打磨完成 → 30_三进阶 (出锅了·Output)
不再活跃 → 40_四归藏 (存起来·Archive)
支撑以上所有 → 00_万法 (开箱即用·Hub)
```

每一篇笔记，都在这五个阶段中的一个。放对位置，找东西就靠直觉。

> **这套结构可以直接从配套的 Obsidian 模板导入，不用自己创建。**

---

## 五区详解

当你用了一段时间，想更深入理解每个区的设计意图：

| 区                      | 代号   | 心法                    | 放什么                    |
| ---------------------- | ---- | --------------------- | ---------------------- |
| `00_万法 (开箱即用·Hub)`     | 驱动引擎 | 只有定好规矩，生产线才能高效运转      | 模板、提示词库、SOP、底层规则       |
| `10_一心 (随手丢·Inbox)`    | 捕捉火种 | 记录要快，不排版，不纠结          | 零散灵感、客户痛点、脑洞碎片、每日日记    |
| `20_二旋 (磨一磨·Lab)`      | 磨练交付 | 弄脏双手，允许极度混乱，只要有产出     | 草稿、正在调试的代码、没跑通的 AI 工作流 |
| `30_三进阶 (出锅了·Output)`  | 升维结晶 | 绝对干净整洁，这是核心资产和护城河     | 定稿文章、交付级 SOP、可直接发布的课件  |
| `40_四归藏 (存起来·Archive)` | 万物归根 | 不再占用心智，交给全局搜索，化作未来的底肥 | 废弃草稿、过期项目、旧备份          |

**判断口诀：自己用 → 万法；给别人用 → 三进阶。**

## 流转规则

```
灵感涌现 → 10_一心 (随手丢)
     ↓ 决定动手
施工打磨 → 20_二旋 (磨一磨)
     ↓ 打磨完成
交付结晶 → 30_三进阶 (出锅了)
     ↓ 不再活跃
归档沉淀 → 40_四归藏 (存起来)
```

**每周巡视一次 10_一心**：躺了一个月没动的想法，直接归档。流动即生命。

## 四件事自检

| 标准 | 问题 | 你的现状 |
|------|------|:---:|
| 能存 | 你有没有一个固定的地方放想法？ | ✅ / ❌ |
| 能连 | 存下来的东西之间有没有建立连接？ | ✅ / ❌ |
| 能查 | 三个月前写的东西，你现在能找到吗？ | ✅ / ❌ |
| 能复用 | 一年前的方法论，你现在还在用吗？ | ✅ / ❌ |

> 四件事都打 ✅，你的系统就成了。工具不重要，Obsidian、Notion、Markdown 文件都可以。重要的是你有没有开始建设。
