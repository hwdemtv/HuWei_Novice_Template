# 🧠 第二大脑·架构设计

> 把 Obsidian CC 的 8 大能力（排除微信 Bot）融入现有五区架构，让 Claudian 从「coding agent 侧栏」升级为「知识演化引擎」。

---

## 一、映射关系：五区 × 三层记忆

现有五区已经是完美的知识生命周期结构，不需要推翻重建：

| 五区（现有） | Obsidian CC 概念 | 记忆层级 | AI 权限 |
|---|---|---|---|
| **10_一心 (Inbox)** | `raw/` + `memory/inbox/` | 原始材料 + 候选记忆 | 只读原始 / 可写候选 |
| **20_二旋 (Lab)** | 加工区 | 消化中间产物 | 可读写 |
| **30_三进阶 (Output)** | `sources/reports/` | 成品输出 | 可读写 |
| **40_四归藏 (Archive)** | 归档区 | 不再常看的沉淀 | 可读写 |
| **00_万法 (Hub)** | 技能/模板/画像 + 长期记忆 | 系统配置 + 个人知识资产 | 部分只读 / 部分弹确认 |

### 长期记忆分区（放在万法下）

```
00_万法 (开箱即用·Hub)/
  ├── 01-07_*                 ← 现有：模板/课程/技能/画像（只读）
  └── 08_长期记忆/             ← 新增：结构化长期记忆（弹确认写入）
      ├── people/              ← 关于人的记忆
      ├── projects/            ← 项目记忆
      ├── wiki/                ← 知识词条
      └── decisions/           ← 决策记录
```

> **为什么放万法？** 00_万法是系统的「弹药库」——模板、课程、技能是通用工具，长期记忆是个人知识资产。统一放在万法下，便于 Agent 一次性读取「系统配置 + 个人上下文」，召回效率最高。01-07 只读，08 弹确认。

## 二、8 大能力 × 落地方式

### 能力 1：消化→沉淀管线

**Slash Command**: `/digest`

```
流程：
10_一心/某篇笔记.md
  ↓ /digest 触发
  ↓ Agent 读取 → 提炼要点
  ↓ 搜索 00_万法/08_长期记忆/ 同主题
  ↓ 矛盾检测（见能力7）
  ↓ 输出到 10_一心/_候选记忆/（附 ⚠️ 标记）
  ↓ 等用户 /apply-memory 确认
```

**Claude Command 文件**: `.claude/commands/digest.md`

### 能力 2：批量清账

**Slash Command**: `/batch-digest`

```
流程：
扫描 10_一心/ 全部未消化材料
  ↓ 逐个轻量提炼 → 产出一张路由表
  ↓
  ┌──────────────────────────────────────────┐
  │ 材料         建议归档     理由            │
  ├──────────────────────────────────────────┤
  │ 文章 A       40_四归藏/   外部参考        │
  │ 截图 B       _候选记忆/   候选记忆        │
  │ 笔记 C       20_二旋/     加工草稿        │
  │ 截图 D       跳过         已有重复        │
  └──────────────────────────────────────────┘
  ↓
  你一次确认 → 批量执行
```

**Claude Command 文件**: `.claude/commands/batch-digest.md`

### 能力 3：三层召回

**Slash Command**: `/ask-vault`

```
① 问库召回：搜全库 → 带引用链接返回
② 陈旧度召回：90天没碰的相关笔记优先顶出
③ 相关笔记面板：当前编辑时自动提示（靠 Claudian 的侧栏）
```

**Claude Command 文件**: `.claude/commands/ask-vault.md`

### 能力 4：费曼学习法

**Slash Command**: `/feynman`

已有 `00_费曼学习法/` 完整体系，AI 技能是对它的自动化：
```
在任意笔记上 /feynman
  ↓ Agent 扮演好奇新手
  ↓ 围绕笔记逐个追问
  ↓ 指出含糊/矛盾处
  ↓ 给出"理解完整度"评估
  ↓ 纯只读，不改笔记
```

**Claude Command 文件**: `.claude/commands/feynman.md`

### 能力 5：写入纪律（四道闸）

**配置文件**: `.claude/CLAUDE.md` 中的权限规则

```
路径权限路由：
  00_万法/01-07_*       → 只读（保护模板和课程）
  00_万法/08_长期记忆/   → 弹确认（长期记忆需人审）
  10_一心/原始材料/      → 只读（原始素材不可改）
  10_一心/_候选记忆/     → 放行（Agent 写候选区）
  20_二旋/              → 放行（加工区自由读写）
  30_三进阶/            → 放行（成品区自由读写）
  40_四归藏/            → 放行（普通归档）
  .obsidian/            → 拒绝（保护配置）
  .claude/              → 拒绝（保护配置）
  .claudian/            → 拒绝（保护配置）
  YOLO 模式             → 全放行（谨慎使用）
```

**落地方式**: Claudian 的 `permissionMode` + `canUseTool` 钩子 + CLAUDE.md 规则

### 能力 6：画像系统（发现式建档）

**Slash Command**: `/init-profile`

```
首次启动
  ↓ 扫描全库 .md 文件（索引鸟瞰）
  ↓ 抽样深读 5-10 篇代表性笔记
  ↓ 生成画像文件：
    00_万法/07_第二大脑/profile/用户画像.md
    00_万法/07_第二大脑/profile/工作模式.md
    00_万法/07_第二大脑/profile/风格偏好.md
    00_万法/07_第二大脑/profile/记忆策略.md
  ↓ 用户确认 → 写入 CLAUDE.md 的 persistent context
```

**Claude Command 文件**: `.claude/commands/init-profile.md`
**画像存储**: `00_万法 (开箱即用·Hub)/07_第二大脑/profile/`

### 能力 7：记忆矛盾检测

**集成在 `/digest` 和 `/apply-memory` 中**

```
digest 新记忆时：
  ↓ 搜索 00_万法/08_长期记忆/ 同主题
  ↓ Agent 对比新旧：
    - 直接矛盾 → ⚠️ 列冲突
    - 过时覆盖 → supersedes 链
    - 重复 → 合并建议
  ↓ 输出裁决清单 → 用户决定
```

**Slash Command**: `/apply-memory`
**Claude Command 文件**: `.claude/commands/apply-memory.md`

### 能力 8：周回顾 + nudge

**Slash Command**: `/weekly-review`

```
Agent 按用户工作模式生成：
  - 本周新增笔记（10→20→30 流动统计）
  - 知识库健康度（未消化数量、矛盾数量）
  - 待确认候选记忆清单
  - 下周建议
  ↓ 落在 10_一心/周回顾/YYYY-WW.md
```

**Claude Command 文件**: `.claude/commands/weekly-review.md`

## 五、与 Claudian 配置的关系

现有 Claudian 设置（`.claudian/claudian-settings.json`）：
- `permissionMode: "yolo"` → 改为 `"default"`，让写入纪律生效
- `model: "opus"` → 保持不变
- `providerConfigs` → 保持不变

新增 CLAUDE.md 作为 Agent 的项目指令，覆盖路径权限、记忆结构、技能调用规范。
