# L10 | 从灵感变成草稿

> [!tip] 💡 你将收获
> - 学会使用「加工笔记」模板，把火种变成结构化草稿
> - 理解 Inbox → Lab 的流转时机
> - 亲手把一条火种搬进 Lab 并完成初稿

---

## 👀 看：同一个想法，在两个区长什么样

打开这两个文件对比一下：

- `10_一心 (随手丢·Inbox)/示例-今天想写一篇关于效率工具的对比.md` — 只有几行字，一个模糊的想法
- `20_二旋 (磨一磨·Lab)/示例-效率工具对比.md` — 有了核心观点、大纲、草稿

**同一件事，两个阶段。区别在于：你有没有「动手」。**

> [!note] 💡 课程注释
> Inbox 是「记录」，Lab 是「加工」。记录只需要 60 秒，加工可能需要 30 分钟到几天。关键区别：Inbox 里你不需要想清楚，Lab 里你需要开始**结构化思考**。

---

## 🧠 解：加工笔记模板的结构

加工笔记模板只有四个部分：

```markdown
## 🎯 核心观点
> 用一句话说清楚这篇笔记要表达什么

## 📝 大纲
- 要点 1：
- 要点 2：
- 要点 3：

## ✍️ 正文草稿
（从大纲展开，写成完整的段落）

## ✅ 发布检查
- [ ] 核心观点是否清晰？
- [ ] 是否有错别字？
- [ ] 是否可以发出去了？
```

**为什么先写核心观点？**

因为你需要在动笔之前想清楚：**这篇文章到底要说什么？**

如果一句话说不清，说明你还没想清楚。这时候不要急着写正文——先去查资料、问 AI、找案例，把核心观点锤实。

### 什么时候该把火种搬进 Lab？

| 条件 | 判断 |
|------|------|
| 这个想法我愿意花 30 分钟以上去展开 | → 搬进 Lab |
| 这个想法一周了还是只有标题 | → 归档或删除 |
| 这个想法和我正在写的东西有关 | → 搬进 Lab |
| 这个想法只是「先存着」 | → 留在 Inbox |

## 🔨 做：把一条火种变成草稿

### Step 1｜选一条火种

打开 `10_一心 (随手丢·Inbox)`，找一条你觉得最值得展开的火种笔记。

如果还没有，现在就用灵感捕获模板创建一条：

```
💡 想写一篇关于______的文章
触发来源：______
```

### Step 2｜搬到 Lab

**方法 A：用命令面板移动（推荐）**

1. 在左侧文件列表中，**点击**你要移动的那条火种笔记
2. 按 `Ctrl + P` 打开命令面板
3. 输入 `move file to`，选择 **Move file to…**
4. 在弹出的文件夹列表中，选择 `20_二旋 (磨一磨·Lab)`
5. 笔记会自动从 `10_一心 (随手丢·Inbox)` 移到 Lab

**方法 B：拖拽移动**

1. 在左侧文件列表中，找到 `10_一心 (随手丢·Inbox)` 文件夹
2. 展开它，**按住**你要移动的笔记，直接**拖到** `20_二旋 (磨一磨·Lab)` 文件夹上松开

移动完成后，接着插入模板：

1. 按 `Ctrl + P` 打开命令面板
2. 输入 `templater`，选择 **Templater: Open insert template modal**（快捷键 `Alt + E`）
3. 在模板列表中选择 **模板-加工笔记**
4. 模板内容会自动插入到笔记中
![[在文档中插入模版.png]]

> [!tip] 💡 或者更简单
> 直接在笔记头部手动输入以下内容即可，不需要插件：
> ```
> ## 🎯 核心观点
> > 用一句话说清楚这篇笔记要表达什么
> 
> ## 📝 大纲
> - 要点 1：
> - 要点 2：
> - 要点 3：
> 
> ## ✍️ 正文草稿
> （从大纲展开，写成完整的段落）
> 
> ## ✅ 发布检查
> - [ ] 核心观点是否清晰？
> - [ ] 是否有错别字？
> - [ ] 是否可以发出去了？
> ```

### Step 3｜填写核心观点

用一句话回答：**这篇文章到底要说什么？**

> [!example] 示例
> 火种：「想写一篇关于效率工具的对比」
> 核心观点：「Notion 是"团队协作的白板"，Obsidian 是"个人思考的第二大脑"——选错工具不是你的问题，是被营销搞混了」

### Step 4｜列大纲

围绕核心观点，列出 3-5 个要点。

### Step 5｜写正文草稿

从大纲展开。**不需要完美，写完就行。**

### Step 6｜更新笔记状态

在笔记顶部的 frontmatter 中，把 `status` 从 `火种` 改为 `加工中`：

```yaml
status: 加工中
```

> [!check] ✅ 验证清单
> - [ ] 有一条火种被搬进了 Lab
> - [ ] 核心观点能用一句话说清
> - [ ] 大纲有 3-5 个要点
> - [ ] 正文草稿至少写了 200 字
> - [ ] frontmatter 中 status 已改为 `加工中`

## 🎯 变：不同场景的加工方式

### 按内容类型

| 你写的类型 | 加工重点 |
|-----------|---------|
| 观点文章 | 先锤核心观点，再找案例支撑 |
| 知识分享 | 先列知识点，再找通俗类比 |
| 复盘总结 | 先写「发生了什么」，再写「学到了什么」 |
| 教程指南 | 先列步骤，再补充截图和注意事项 |

### 跨域迁移：同一个模板，不同的人用

| 场景 | 你的「火种」 | 核心观点写什么 | 大纲怎么列 |
|------|------------|-------------|-----------|
| ✍️ 写公众号 | 一个灵感/观点 | 这篇文章的核心论点 | 3-5 个段落要点 |
| 🎓 学生备考 | 一个课堂困惑 | 这个概念的本质是什么 | 知识点 → 薄弱点 → 关联 |
| 💼 职场复盘 | 一次踩坑经历 | 根因是什么 + 规则是什么 | 踩坑 → 根因 → 规则 → 验证 |
| 📚 读书输出 | 一个可迁移的概念 | 原概念 + 迁移场景 | 概解 → 关联 → 迁移 → 应用 |

> 同一个「核心观点 → 大纲 → 正文 → 检查」的结构，填入不同的内容就是不同的产出。
