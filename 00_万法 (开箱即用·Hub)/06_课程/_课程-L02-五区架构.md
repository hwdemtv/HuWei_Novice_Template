# L02 | 为什么文件夹只分两层就够了

> [!tip] 💡 你将收获
> - 彻底理解五区架构的设计逻辑
> - 知道一条笔记该放哪个区
> - 掌握「生命周期分类」思维，告别「按主题建文件夹」

---

## 👀 看：两种组织方式的对比

### ❌ 大多数人的做法：按主题分类

```
📁 工作/
  📁 项目A/
    📁 会议记录/
    📁 方案/
  📁 项目B/
📁 学习/
  📁 Python/
  📁 读书笔记/
📁 生活/
  📁 健身/
  📁 旅行/
```

三个月后：**找不到东西**。因为你忘了当初是按「项目」分的还是按「类型」分的。而且一个笔记可能同时属于「工作」和「学习」。

### ✅ 这套系统的做法：按生命周期分

```
📁 00_万法 (Hub)     ← 工具和规则（不动）
📁 10_一心 (Inbox)   ← 刚进来的（还没想好）
📁 20_二旋 (Lab)     ← 正在搞的（动手了）
📁 30_三进阶 (Output)← 搞定了的（可以交付）
📁 40_四归藏 (Archive)← 不搞了的（归档）
```

> [!note] 💡 课程注释
> 核心区别：**主题分类是静态的**（一个笔记只能属于一个文件夹），**生命周期是动态的**（笔记会在区域间流转）。你不需要想「这个笔记该放哪」，只需要想「这个笔记现在处于什么阶段」。

---

## 🧠 解：五区架构的设计逻辑

### 每个区的「心法」

| 区 | 代号 | 心法 | 放什么 |
|---|------|------|--------|
| `00_万法 (Hub)` | 驱动引擎 | 只有定好规矩，生产线才能高效运转 | 模板、方法论、Prompt、规则 |
| `10_一心 (Inbox)` | 捕捉火种 | 记录要快，不排版，不纠结 | 零散灵感、脑洞碎片、每日日记 |
| `20_二旋 (Lab)` | 磨练交付 | 弄脏双手，允许极度混乱，只要有产出 | 草稿、调试记录、没跑通的工作流 |
| `30_三进阶 (Output)` | 升维结晶 | 绝对干净整洁，这是核心资产和护城河 | 定稿文章、交付级 SOP、可发布的课件 |
| `40_四归藏 (Archive)` | 万物归根 | 不再占用心智，交给全局搜索 | 废弃草稿、过期项目、旧备份 |

### 判断口诀

> **自己用 → 万法；给别人用 → 三进阶。**

这条口诀解决 80% 的归类困惑：
- 写了一个 SOP 给团队用？→ `30_三进阶`
- 写了一个 SOP 给自己参考？→ `00_万法`
- 写了一篇文章准备发布？→ `30_三进阶`
- 记了一个灵感？→ `10_一心`

### 流转规则

```
灵感涌现 → 10_一心 (Inbox)
     ↓ 决定动手
施工打磨 → 20_二旋 (Lab)
     ↓ 打磨完成
交付结晶 → 30_三进阶 (Output)
     ↓ 不再活跃
归档沉淀 → 40_四归藏 (Archive)
```

**每周巡视一次 Inbox**：躺了一个月没动的想法，直接归档。**流动即生命。**

### 三条铁律

| # | 铁律 | 为什么 |
|---|------|--------|
| 1 | 文件夹不超过两层 | 超过两层你就不会用了 |
| 2 | 每周清理 Inbox | 不清理就会变成垃圾堆 |
| 3 | 以输出为导向 | 不产出的笔记没有价值 |

## 🎯 变：设计你的命名规范

你现在用的是默认命名。等你用熟了，可以改成自己的：

| 你的场景  | 建议命名                                   |
| ----- | -------------------------------------- |
| 做内容创作 | Inbox / Draft / Published / Archive    |
| 做项目管理 | Ideas / In-progress / Done / Archived  |
| 做学术研究 | Topics / Reading / Writing / Published |

命名不重要，**思维方式才重要**——你的笔记处于什么阶段，就放在什么阶段。
