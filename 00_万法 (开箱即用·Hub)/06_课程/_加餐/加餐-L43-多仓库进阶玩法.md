## 👀 看：单库变重的三个信号

一个熟悉的场景：

> 你用本仓库跑了一年：工作项目、AI 学习笔记、家人健康记录、课程素材，全在一个库里。某天同事想借你的项目库参考，你打开一看——体检报告和读书笔记就躺在项目文件夹旁边。分享？先花半小时做隐私排查。

哪些信号说明你在接近天花板：

| 信号 | 典型表现 | 本质问题 |
|------|---------|---------|
| 读者混杂 | 同一个库要给不同的人看/不给看 | 隐私边界 |
| 节奏冲突 | 工作区天天迭代，生活区月更，混在一起互相干扰 | 更新节奏 |
| 域已成熟 | 某个领域已经长出自己的 10→20→30 完整循环 | 系统成熟 |

反过来也要看清代价：**双链密度是单库最大的红利**。笔记之间的意外连接（刷到旧笔记、图谱上的邻近节点）只发生在同一个索引里。库一分，网就撕碎了——新手期分库，等于还没织网先剪线。

## 🧠 解：三条原则

### 原则 1｜先问「该不该分」，再问「怎么分」

三条判断线，逐条过：

> [!warning] 🚦 分库判断线
> 1. **读者不同** → 分（给谁看、不给谁看，是隐私问题不是整理问题）
> 2. **节奏不同** → 分（日更区和月更区互相拖累）
> 3. **隐私边界** → 必分（健康、财务、家庭记录，物理隔离最保险）
>
> 三条都不满足 → **不分**。用本仓库的五区架构 + 标签解决——五区本身就是为「一个库里有不同节奏」设计的。

### 原则 2｜分了之后，链接怎么办

Obsidian 原生双链**不跨库**——这是刻意的安全设计，不是缺陷。第三方工具 **Obsidian Hub**（Windows 11 多仓库启动器 + 配套 Bridge 插件）补上这块：

```md
@工作仓库[[项目/计划]]
@资料库[[网络/TCP|TCP 协议]]
```

- 在编辑器输入 `@` → 先选仓库 → 逐层浏览文件夹和笔记；输入文字可递归搜索
- 跨库链接是**独立语法**，和原生 `[[双链]]` 互不干扰——单库内的链接规矩（[[00_万法 (开箱即用·Hub)/06_课程/_课程-L05-双向链接与图谱|L05]]）一条不变
- 点击跨库链接**默认只读预览**，确认有用再跳目标库——防止「顺手改错库」

### 原则 3｜跨库引用的三条纪律

Hub 的设计原则和本仓库的写入纪律惊人地同源，对照着记：

| Hub 的设计 | 本仓库的对应 |
|-----------|-------------|
| 默认只读，预览优先于打开 | 原始笔记 🔒 只读，Agent 不改原始素材 |
| 仅用户显式操作时写入 | 长期记忆 ⚠️ 弹确认，绝不静默合并 |
| 改名断链明示，绝不按标题猜测 | 记忆引用 ID 优先，失效标 ⚠️ 断链 |

一条要记住的边界：**仓库 ID 稳定 ≠ 笔记路径稳定**。笔记改名或移动后，已有的跨库链接不会自动修复，会明确显示断链——这是「明示」优于「猜测」的代价，也是本仓库 frontmatter 里库内来源一律用 wikilink（Obsidian 会自动更新）的原因。

> [!note] 💡 课程注释
> Hub 内置的四库工作流（Echo 灵感 → Main 认知 → Output 输出 + Knowledge 资料库）和本仓库的 10_一心 → 20_二旋 → 30_三进阶 + 00_万法 完全同构——两套系统在互相不知情的情况下收敛到了同一个知识流形状。这本身就是对「输入→加工→输出」这条主线的第三次独立验证。

## 🔨 做：装一次，链一条

**Step 1**｜从 GitHub Releases（`LeeDaud/Obsidian-Hub`）下载安装包，安装并启动 Hub，把已有的仓库添加进去。

**Step 2**｜在仓库条目里安装 Bridge 插件（Hub 会自动写入启用列表），若该仓库的 Obsidian 正在运行，重启一次。此后无需 Hub 常驻。

**Step 3**｜在任意笔记里输入 `@`，选择另一个仓库，浏览并选中一条笔记——一条 `@仓库[[路径]]` 跨库链接就存好了。

**Step 4**｜点击这条链接：默认只读预览；点「在目标仓库打开」才会真正跳过去。回头点一条原生 `[[双链]]`，确认两者互不影响。

> [!check] ✅ 验证清单
> - [ ] 一条 `@仓库[[路径]]` 跨库链接已保存，且可只读预览
> - [ ] 原生 `[[双链]]` 行为不变（抽一条点开验证）
> - [ ] 说得出自己的「分 / 不分」答案和理由（对照三条判断线）

## 🎯 变：三种典型多库布局

| 布局 | 适合谁 | 隔离的是什么 |
|------|--------|-------------|
| 工作 / 生活双库 + 共享资料库 | 笔记重度用户 | 隐私与节奏；资料库两边引用 |
| 主库 + 项目库 | 有明确项目制的人 | 项目归档不污染主库，结项即封库 |
| 内容库 + 学员库（做课的人） | 知识博主 / 训练营讲师 | 课程内容（系统区）与学员数据（用户区）物理隔离 |

共同点：**每个库内部仍然是完整的 10→20→30 循环**——分库分的是边界，不是流程。
