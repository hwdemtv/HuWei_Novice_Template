# /apply-memory — 确认候选记忆归档

## 参数
$CANDIDATE: 指定候选记忆文件路径（可选，不指定则列出全部待确认记忆）

## 流程

### 如果未指定 $CANDIDATE

1. **扫描** `10_一心/_候选记忆/` 下所有 `status: pending` 的文件
2. **展示清单**：

```markdown
# 📥 待确认候选记忆（{N} 条）

| # | 标题 | 来源 | 冲突 | 日期 |
|---|------|------|------|------|
| 1 | Rust错误处理 | note-001.md | ⚠️ 有冲突 | 2026-07-10 |
| 2 | 费曼学习法理解 | note-003.md | ✅ 无冲突 | 2026-07-11 |
```

3. 用户选择编号 → 进入单条确认流程

### 单条确认流程

1. **展示候选记忆全文**
2. **如果有关联长期记忆** → 展示对比
3. **矛盾检测**：
   - 直接矛盾 → 列出两条记忆，让用户选择：
     - "A 对 B 错" → B 标记为 `superseded-by: A`
     - "都对，不同场景" → 两条都保留，加交叉引用
     - "需要修改后合并" → 让用户给出修改方向
   - 过时覆盖 → 展示新旧对比，用户确认后执行覆盖
   - 重复 → 建议合并方案，用户确认后执行
4. **选择归档位置**：
   - people/ — 关于某个人
   - projects/ — 项目相关
   - wiki/ — 知识词条
   - decisions/ — 决策记录
5. **用户确认** → 写入 `00_万法/08_长期记忆/{分类}/`
6. **更新候选记忆** → status 改为 confirmed

## 输出格式（长期记忆）

```markdown
---
title: {标题}
source: "[原始来源路径]"
confirmed: {日期}
tags:
  - 长期记忆
  - {主题}
supersedes: []  # 如果覆盖了旧记忆
related: []     # 相关记忆路径
---

# {标题}

{正文内容}
```

## 注意
- 绝不静默合并
- 每一步都要用户确认
- 写入前展示完整内容预览
- 如果是覆盖旧记忆，在旧记忆的 frontmatter 加 `superseded-by: [新记忆路径]`
