# /digest — 消化笔记

## 参数
$FILE_PATH: 要消化的笔记路径（如果不指定，默认消化当前活动文件）

## 流程

1. **读取** `$FILE_PATH` 的全部内容
2. **提炼** 核心知识点（不是总结全文，是提取可长期记住的知识）
3. **搜索** `00_万法/08_长期记忆/` 下是否有同主题记忆
4. **矛盾检测**：
   - 如果找到相关记忆 → 对比新旧，判断关系（矛盾/过时/重复/补充）
   - 矛盾 → 打 ⚠️ 标记，列出冲突点
   - 过时 → 标记为 `supersedes: [旧记忆路径]`
   - 重复 → 标记为 `duplicates: [已有记忆路径]`
   - 补充 → 标记为 `extends: [已有记忆路径]`
5. **输出候选记忆**：写入 `10_一心/_候选记忆/` 目录
   - 文件名：`候选-{关键词}-{YYYYMMDD}.md`
   - 格式包含：frontmatter（title/source/created/tags/status/conflicts）+ 正文
6. **汇报**：告诉用户消化了什么、发现了什么冲突、建议怎么处理

## 输出格式

```markdown
---
title: 候选记忆 - {标题}
source: "[原始文件路径]"
created: {日期}
tags:
  - 候选记忆
  - {主题标签}
status: pending  # pending / confirmed / rejected
conflicts: []    # 冲突列表
---

# {标题}

## 核心知识点
{提炼的知识点}

## 与现有记忆的关系
{如果无冲突：写"新知识，无冲突"}
{如果有冲突：列出冲突详情}
```

## 注意
- 绝不直接写入 `00_万法/08_长期记忆/`
- 原始文件只读，不做任何修改
- 如果当前文件太短（<100字），提示用户内容不足
