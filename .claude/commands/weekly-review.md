# /weekly-review — 周回顾

## 参数
$WEEK: 可选，指定周（如 2026-W28），默认本周

## 流程

1. **统计本周数据**：
   - 扫描 `10_一心/`、`20_二旋/`、`30_三进阶/` 下最近 7 天新增/修改的文件
   - 统计笔记流转：读 `20_二旋/`、`30_三进阶/` 笔记 frontmatter 的 `origin` 字段——origin 指向 10_一心 的条数 = 真实 10→20 流转；无 origin 的单独计「未挂来源」（30_三进阶 无 origin 的按修改时间估算并注明口径）
   - 统计 `10_一心/_候选记忆/` 下待确认数量
   - 统计 `00_万法/08_长期记忆/` 本周新增数量

2. **健康度检查**：
   - 未消化数量（10_一心/ 里 digested != true 的数量）
   - 候选记忆积压（_候选记忆/ 里 status: pending 的数量）
   - 矛盾数量（有 conflicts 标记的候选记忆）
   - 断链数量（候选/长期记忆里 source、origin 引用失效，且按 id 全库搜索也未命中的条数）

3. **生成本周回顾**：

```markdown
---
title: 周回顾 {YYYY-WW}
created: {日期}
tags: [周回顾]
---

# 📅 周回顾 · {YYYY-WW}（{日期范围}）

## 📊 本周数据

| 指标 | 数值 |
|------|------|
| 新增笔记 | {N} 篇 |
| 加工中 | {N} 篇 |
| 出锅成品 | {N} 篇 |
| 新增长期记忆 | {N} 条 |
| 候选记忆待确认 | {N} 条 |

## 🔄 笔记流转

```
10_一心 ({N}篇) → 20_二旋 ({N}篇) → 30_三进阶 ({N}篇)
```

> 数据口径：{N} 篇 20_二旋 笔记已挂 origin 来源（未挂 {N} 篇）

本周流转效率：{高/中/低}（产出/输入比 = {X}%）

## ⚠️ 健康提醒

- {如果未消化 >20}：10_一心 积压 {N} 篇未消化，建议运行 /batch-digest
- {如果候选记忆 >10}：{N} 条候选记忆等待确认，建议运行 /apply-memory
- {如果矛盾 >0}：{N} 条记忆冲突未解决
- {如果断链 >0}：{N} 条记忆来源断链（找不到源头笔记），建议运行 /apply-memory 逐条修复或裁决

## 📝 本周亮点
- {列出本周最有价值的3篇笔记/记忆}

## 🎯 下周建议
- {基于本周数据的1-3条建议}
```

4. **写入** `10_一心/周回顾/{YYYY}-W{WW}.md`

## nudge 机制（非命令触发）

当 Agent 在对话空状态收到消息时：
- 检查上次周回顾日期
- 如果距离上次周回顾 >7 天 → 温和提示"要不要生成上周回顾？"
- 用户说"不要"或"稍后" → 标记跳过，下周再问
- 绝不唠叨
