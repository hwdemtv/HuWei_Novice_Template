# /batch-digest — 批量清账

## 流程

1. **扫描** `10_一心/` 下所有笔记（排除 `_候选记忆/` 和 `周回顾/` 子目录）
2. **过滤**：跳过已有 `digested: true` frontmatter 的文件
3. **逐个轻量提炼**：每篇提取标题 + 关键词 + 一句话摘要
4. **分类路由建议**：

| 分类 | 目标路径 | 判断标准 |
|------|----------|----------|
| 外部参考 | `40_四归藏/` | 外部文章剪藏、参考资料 |
| 候选记忆 | `10_一心/_候选记忆/` | 值得长期记住的知识点 |
| 加工草稿 | `20_二旋/` | 有潜力变成成品的内容 |
| 已有重复 | 跳过 | 与现有笔记高度重复 |
| 直接归档 | `40_四归藏/` | 已完成、不再需要加工的内容 |

5. **生成路由表**：

```markdown
# 📋 批量清账报告 {YYYY-MM-DD}

共扫描 {N} 篇笔记，其中 {M} 篇未消化。

| # | 文件 | 建议去向 | 理由 | 关键词 |
|---|------|----------|------|--------|
| 1 | xxx.md | _候选记忆/ | 核心知识点 | Rust, 错误处理 |
| 2 | yyy.md | 20_二旋/ | 有展开价值 | 效率工具 |
| 3 | zzz.md | 跳过 | 已有重复 | - |
```

6. **等用户确认** → 用户可以说"全部执行"或"只执行 1,3,5"
7. **批量执行**：移动文件 + 在原文件加 `digested: true` 标记
8. 被标记为 `_候选记忆/` 的文件，同时触发 `/digest` 的消化流程

## 注意
- 这是 O(1) 次交互处理 O(n) 篇笔记
- 如果笔记数量 >30，分批处理，每批最多 30 篇
- 始终先展示路由表，等用户确认后才执行移动
